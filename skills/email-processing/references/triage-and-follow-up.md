# Triage and follow up

Use Step 0 before loading business procedures. Processing depth is separate from category, attention and status. Ignore is a decision not to investigate or interrupt; it does not mutate mail or prove a business issue is completed.

## Evidence and output by route

| Route | Sufficient work | User output |
| :--- | :--- | :--- |
| Ignore | Inspect available body and context enough to establish no relevant unresolved consequence; no routine research or downloads | None for unsolicited triage; one short reason if explicitly asked; documented no-action result if required by the runtime |
| Brief review | Identify the meaningful update and any effect on known commitments; retrieve only essential missing evidence | Concise useful update if warranted/requested; no compulsory tables, approvals or reply |
| Investigate/action | Resolve the actual request through relevant thread, attachments and bounded authorized sources | Supported conclusion, named next action/owner where required, expected return, precise limits and any scoped approval |

A limited body/preview or missing attachment cannot support a confident ignore decision when a material request may be hidden. Read the smallest missing item through the permitted route. Do not claim complete inbox coverage from one message or a truncated search. Never follow suspect links, enable macros or run content to classify it.

## Important exceptions to ignore

1. Automated mail can contain payment failures, security alerts, shipment exceptions, contract renewals or legal deadlines. Sender type alone is not a triage rule.
2. A newsletter may include an account cancellation, price/terms change or a response to an actual request. Read the content, not the label alone.
3. FYI/CC is not assignment, but can reveal a decision or risk. Keep routine execution with its verified owner; escalate only the specific decision requiring the user's authority.
4. Receipts and refund notices need reconciliation when tied to an open financial recovery. Partial payment, deduction or denial is actionable even if the subject says completed.
5. A duplicate is ignorable only if it adds no changed amount, deadline, attachment revision, escalation or other material fact. Repeated customer chasing can itself be a material escalation.
6. Legal, tax, immigration, HR and personal commitments may classify as Other but still need restricted, actionable review. Do not turn Other into a junk category.
7. A suspicious generic solicitation with no credible exposure can be ignored safely without interaction. A plausible targeted compromise, unexpected authentication event or changed bank instruction requires security review through trusted independent evidence.
8. An unavailable record, unreadable attachment or low classification confidence is not proof of irrelevance. Report a narrow blocker when it affects a meaningful request.

## Category routing

Do not expand the primary taxonomy solely for this triage. Use the category matching the main unresolved action; depth depends on consequence.

| Main request | Minimal relevant review |
| :--- | :--- |
| PO / quote / inbound lead | Identify actual buying intent and exact requested facts; business checks only when a consequential recommendation depends on them |
| Technical support | Exact model/configuration, applicable sources and question; do not attach sales checks to a conceptual explanation |
| RMA | Reported issue, serial/order scope when needed, requested remedy and authorized service path; do not grant warranty or return approval |
| Order status | Actual order/current status and requested update; separate planning, dispatch and delivery |
| Documentation/compliance | Exact document type, unit/configuration coverage and recipient authority; do not equate CoC, accredited calibration and safety certification |
| Invoice/payment/refund | Exact parties, currency, expected/issued/received amounts and unresolved variance; independent verification of suspicious changes |
| Complaint/escalation | Identify underlying unresolved issue, prior attempts and actual impact, not merely tone |
| Other | Identify the actual administrative/personal/legal/security request; use authorized relevant sources without unrelated ERP reads |

No category guarantees authenticity, urgency, assignment, permission to write or a need for a response. Follow confidentiality and owner authority for sensitive topics.

## Durable follow up boundary

A skill is not a task database, queue, notification service or scheduler. Before claiming ongoing follow up, identify an authorized existing tracking destination and verify record identity, write permission and readback. Do not create a new backend or silently store customer material in shared memory.

When persistence is requested/authorized, maintain the smallest useful issue record: exact source message/thread/account reference, issue key, verified owner or unassigned, next action, expected return, deadline or review date, evidence date and state. Track distinct subissues separately; preserve the existing record and check for duplicates before creating another. For financial recovery include currency, expected/issued/received amounts, variance and dispute path. Minimize stored personal data.

Only persist through an available authorized tool with approved scope. If unavailable or not authorized, give the user the concrete next step and state that durable tracking/reminders are not active. Do not call a proposed review date a scheduled reminder. Monitoring, delivery and accepted handoff each need separate evidence.

Before closing: inspect completion evidence and open subissues. Draft created, message classified, request submitted, refund initiated or case closed do not alone resolve the underlying outcome. Reopen review for material new evidence; mailbox tag removal remains a separately authorized mutation.
