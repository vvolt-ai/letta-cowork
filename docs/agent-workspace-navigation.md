# Agent-first workspace navigation

Source/date: Bhavesh approved the screenshot-based desktop navigation plan on2026-11-16. This is the standalone Electron app, not cowork-web or a backend redesign.

## Layout and entry points

The resizable sidebar now contains a narrow agent rail and an independently scrolling conversation column. Flat icon/text actions are Schedules, Remote Access and Emails above New chat. At Bhavesh's2026-11-17 request, the sidebar Memory shortcut and Recent/Favourites dropdown are removed; the rail stays recent-first. Memory data, tools and dialog implementation are unchanged. Settings stays on the rail; existing workspace selection, logout, inbox and resume dialogs remain reachable. Theme variables and existing native-window spacing are preserved. A new installation defaults to336px total sidebar width; valid saved widths still apply. Agents use deterministic initials/gradients because the existing IPC agent payload does not supply a typed avatar URL. No new portrait/network source is inferred from metadata.

Agents are fetched through the current authenticated listLettaAgents IPC. Cached session agents remain available for navigation, and All conversations retains unknown-agent/legacy sessions. Selecting an agent opens that agent's blank composer without creating a server conversation or mutating global environment configuration merely to browse. New chat uses the existing configuration/first-send flow with the correct selected agent. Creating work remains a human send action; an active previous request is not stopped by view selection.

The selected agent's remote non-archived conversation summaries merge with local session metadata by ID. Local names, live status and explicit connection IDs survive; email conversations are included. Opening an uncached conversation reuses openExistingConversation/history hydration rather than creating another session engine. Rename/delete/resume controls are offered once a conversation is locally managed. The current scope's unread/error/status handling remains server-authoritative; no routing, permission or provider grant is fabricated from a UI selector.

Electron conversation listing now follows the installed SDK's public after cursor with one scoped client, descending last-message order and bounded requests. Array and legacy items envelopes remain accepted. Duplicate cursors/no progress, errors and admission/deadline exhaustion fail rather than silently returning a complete-looking truncated list. Limits are100 pages/10000 retained rows/120s; no unbounded loop or model POST/retry is added. Agent/owner changes discard late UI responses; remote snapshots are tagged to their selected agent, and successful data/search remain during same-scope Refresh.

## Recent-first ten-item lists (2026-11-16)

At Bhavesh's follow-up request, the rail shows the10 most recently used agents first; Load more agents adds at most10 each time. Agent rank combines owner-scoped recent selection, cached conversation activity and the provider's last_run_completion when supplied by the existing IPC list. The currently selected agent stays reachable; entries without known usage fall back to stable name ordering rather than fabricated history. Only agent IDs/timestamps are persisted, capped at500 entries per user/workspace storage key; unavailable/corrupt storage does not block navigation or create agents not returned by the authorized catalog/cache.

The conversation list likewise starts with10 recent rows and Load more conversations adds the next10. Search filters the full loaded metadata before taking the visible batch, so older results remain findable without expanding every page. Query/agent/workspace changes restart the visible count; same-scope Refresh preserves it and existing selection/drafts. This is incremental presentation over the already bounded metadata IPC loader, not a claim of lazy10-row network fetching. Browser fixtures cover25 agents,120 remote chats, exact10/20/page-tail counts, active-agent recency and searching beyond the first page.

## Existing Letta favourites API (sidebar selector superseded2026-11-17)

The sidebar no longer exposes or queries the Favourites mode; it always requests the normal catalog and applies recent-first ordering. The optional favourites-only IPC/helper remains available for existing callers and retains its separate tests. When explicitly requested through that helper, favourites are read from the configured Letta connection's verified GET /v1/metadata/user identity and exact favorite:user:<id> agent tag, matching reviewed Letta Code0.34.63 favourites.ts. It does not infer ownership from a Vera user UUID/email, legacy global view:letta-chat, a different account or local pins. The selected connection/API key's upstream identity determines this list; it is not a new per-Vera-user favourites database or an aggregation across unrelated accounts.

The existing listLettaAgents IPC gains an optional favourites-only boolean; earlier callers are unchanged. The favourite query requests agent.tags, uses the SDK cursor iterator, filters/deduplicates only matching verified tags and fails closed if metadata/tag evidence is unavailable. No API keys or metadata/user response are returned to the renderer or logged. Errors show unavailability, not an empty-success/local fallback. There are no tag writes, Add/Remove favourite actions, agent renames/deletes or live account mutations in this feature; maintain favourites in Letta until a separate management UI is implemented.

The sidebar browser fixture now verifies recent-only navigation with no favourites query or list-mode control. API helper tests continue to verify the optional upstream favourites owner/tag query, duplicate filtering, missing/denied metadata, missing tag evidence and no cross-account/local fallback. These tests are mocked; they do not establish live upstream account acceptance.

## State ownership

The Zustand store still owns active session, prompt, model and execution state. composerDrafts is an in-memory per-conversation/new-agent draft map, not persisted preference data. Switching views restores the correct draft; confirmed startup consumes its new-chat draft, failed startup preserves it, authoritative deletion removes its draft and workspace reset clears all drafts. Existing session hydration and running-request/permission state are not replaced. Startup navigation is guarded while pending. The sidebar has no Memory action. The retained Memory dialog and display identity are also scoped to the current authenticated user/workspace so an old target cannot be opened after switching accounts.

Main chat, model/CWD controls, permission/Stop/queue flows, email processing, settings and remote-only build guard remain existing implementations. The empty composer greets the selected agent and omits redundant large pickers once the rail has selected an agent; the old configuration/agent fallback remains when no agent is selected. Schedules/Remote Access/Emails are shortcuts to existing views, not new business-system operations. Unknown/remote conversation access still requires the owning IPC/backend checks.

The2026-11-17 sidebar follow-up removes selector-only state/styles and the Memory shortcut. The browser fixture now asserts these controls are absent and no favourites/Memory requests occur, while preserving recency, paging/search, draft restoration, workspace isolation, running-state preservation and remaining shortcuts. No memory deletion or favourite-tag mutation is part of this change.
